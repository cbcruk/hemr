# 추나 연간 20회 한도

## 요약

- 환자의 추나 시술 이력을 심평원(데스크톱 앱 실시간) 또는 서버 저장본(웹)에서 읽어 **누적 시행 건수**를 셉니다. 기준은 진료의 `기준일시` 연도(1/1 ~ 오늘, 지난 연도면 12/31까지)이고, 자보는 사고접수번호 단위(사고발생일 ~ 오늘)입니다.
- 누적이 `20` 이상이면 `추나횟수소진`입니다. 같은 날 삭제되지 않은 이력이 있으면 `당일추나시술여부`이고, 둘 다 아니어야 `오늘추나시술가능`입니다.
- 건보·급여 진료에서 소진 상태로 추나를 **새로 추가**하면, 실시간 조회일 때는 확인창을 띄우고 그 추나 라인을 넣지 않습니다. 실시간이 아니면 경고 토스트만 띄우고 넣습니다.
- 청구 경고 `I0009`("추나요법 시술 가능 횟수를 초과했습니다.")는 건보·급여(실시간 누적 ≥ 20)와 산재(올해 진료기록 라인 수 + 현재 라인 수 ≥ 20) 두 갈래로 계산됩니다. 표시만 하고 저장·완료를 막지 않습니다.

**판정** (로딩 중이면 모두 `undefined`)

- `본원추나시행건수` = `!삭제여부 && 본원` 행 수, `타원추나시행건수` = `!삭제여부 && !본원` 행 수.
- `누적추나시행건수` = 실시간 `누적횟수 ?? (본원 + 타원)`. 심평원 누적횟수가 `0`이면 `??` 때문에 목록 건수 대신 `0`입니다.
- `추나횟수소진` = `누적 >= 20`.
- `당일추나시술여부` = 어떤 행이 `isSameDay(시술일, 기기의 현재 시각) && !삭제여부`. 진료의 기준일시가 아니라 **기기 오늘** 기준입니다.
- `오늘추나시술가능` = `!당일 && !소진`.
- `실시간조회여부` = 로딩이 끝났고 실시간 결과가 있으면 참.

**청구 경고 I0009**

- 건보·급여(`SFt`): `추나누적횟수`가 `null/undefined`이거나 `< 20`이면 없음. 아니면 현재 진료의 카테고리 `33001005`(추나) 라인이 하나라도 있으면 `{ 에러코드: "I0009", 원인제공자Ids: 그 라인 id 전부 }`. `추나누적횟수`는 실시간 조회일 때만 들어오므로 웹에서는 I0009가 나오지 않습니다.
- 산재(`BFt`): 현재 진료의 수가코드가 `40710` 단순, `40720` 복잡, `40721` 복잡80, `40730` 특수 중 하나인 라인이 있으면, 같은 연도(기준일시 연도) 다른 산재 진료기록의 해당 라인 수 + 현재 라인 수가 `>= 20`이면 I0009. 이력은 `최근진료데이터`(산재는 `max(올해 경과일, 재해발생일 이후 일수, 730)`일)에서 옵니다.
- 경고 메시지: "추나요법 시술 가능 횟수를 초과했습니다." / "추나요법을 삭제해주세요. 유지 시 비급여로 처방됩니다." 위험도 높음. 청구 경고 패널 표시용이며 저장·완료를 막지 않습니다.

**처방 추가 가드** (`v`, 상병·처방 변경과 새 처방 추가 경로)

- 보험구분이 건보·급여가 아니거나 `추나횟수소진 !== true`면 그대로 둡니다.

- `실시간조회여부 !== true`: 경고 "`M/d HH:mm 기준 `추나 누적 20회로 조회됩니다. 이 PC는 심평원 실시간 조회가 되지 않아 처방을 막지 않았습니다. 급여로 청구하면 전액 삭감됩니다." 후 그대로 둡니다.

## 서버 이전 시 주의

- **누적 값의 출처가 클라이언트 밖입니다.** 실시간 값은 데스크톱 앱이 심평원에서 받아오고, 웹은 그 결과를 저장한 스냅샷을 씁니다. 서버가 판정하려면 심평원 조회 결과(목록과 `추나횟수`)를 서버가 보관하고 있어야 하며, 스냅샷이 오래되면 판정도 오래됩니다(`조회시각` 표시가 이 때문에 있습니다).
- **현재 진료의 추나가 이미 포함됐는지 모호합니다.** 자동 승인으로 오늘 추나가 심평원에 들어가면 누적이 그 건을 포함하므로, 20번째 추나를 한 진료 자체에도 I0009가 뜹니다(`>= 20`). 고시가 "20회까지 인정"이면 이 동작은 경계에서 과잉 경고입니다.
- **산재와 건보의 경계가 다릅니다.** 산재 `BFt`는 "이전 + 현재 ≥ 20"이라 20번째에서 경고하고, 건보 `SFt`는 "이전 누적 ≥ 20"이라 21번째에서 경고합니다. 산재는 또 진료 수가 아니라 라인 수를 셉니다. 현재 동작을 그대로 옮기되 버그 후보로 표시합니다.
- **자보:** 같은 상수 20을 사고 단위 목록에 적용해 화면에 `n/20`을 보여주고 자동 승인도 멈추지만, 처방 가드와 청구 경고는 건보·급여만 봅니다.
- **"오늘"은 기기 시각입니다.** 과거 진료를 열어도 당일 여부는 실제 오늘 기준입니다. 서버는 `serviceAt`(진료일) 기준으로 판정해야 하며, 이것은 동작 변경입니다.
- 심평원 누적횟수 `0`은 목록 집계보다 우선합니다.
- 실시간 목록이 300건 × 10쪽을 넘으면 잘리고 콘솔 경고만 남깁니다(과소 집계).
- 웹에서는 가드가 막지 않고 I0009도 나오지 않습니다. 서버가 `CHUNA_ANNUAL_LIMIT`를 완료 차단으로 만들면 웹 사용자에게는 새 차단입니다.
- 한도 20은 `regulatory-limits` 참조데이터로 옮길 대상입니다(`docs/design/clinical.md`).
