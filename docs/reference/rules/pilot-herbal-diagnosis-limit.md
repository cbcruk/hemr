# 첩약 시범사업 질환별 누적 투약 이력 판정

## 요약

- 심평원 누적 투약 이력에서 **선택 질환이 아닌 다른 질환 2개 이상**(공통처방 `00` 제외, 이 기관 등록 `Y`, 누적 1일 이상)이 있으면 처방 불가입니다.
- 선택 질환을 **다른 기관**(`N`)에서 1일 이상 투약받았으면 처방 불가, 본인부담률구분코드는 빈 값이 됩니다.
- 선택 질환을 **이 기관**(`Y`)에서 누적 20일 이상 투약했으면 처방은 되지만 경고하고 본인부담률구분코드를 `U`(전액부담)로 바꿉니다. 20일 미만이면 `G`(일부부담).
- 같은 판정을 두 함수(`Cdn` 화면 문구·처방불가, `$dn` 코드 결정)가 따로 하며, 2개 질환 규칙의 적용 조건이 서로 다릅니다.

## 로직

이력 행 필드: `진료년월`, `첩약상병구분코드`, `해당요양기관등록여부`(`Y` 이 기관 / `N` 타 기관), `첩약상병명`, `누적투약일수`(숫자 문자열).

질환 코드(`M0e`): `00` 공통처방, `01` 월경통, `02` 안면신경마비, `03` 뇌혈관질환 후유증, `04` 알레르기성비염, `05` 요추추간판탈출증, `06` 기능성소화불량. 문구에는 `질환명`(공백 없는 이름)을 씁니다.

**`R0e(이력, 선택코드)`**: `첩약상병구분코드 ≠ "00"`, `≠ 선택코드`, `해당요양기관등록여부.toUpperCase() === "Y"`, `Number(누적투약일수) > 0`인 행의 **서로 다른** 질환 코드 수가 2 이상이면 참.

**`N0e(이력, 선택코드)`**: 선택 코드 행이 없으면 `undefined`. 있으면 첫 행을 바탕으로 `누적투약일수 = max(Number(x) || 0)`(문자열), `해당요양기관등록여부 = 하나라도 "Y"(대문자 정확히)면 "Y", 아니면 "N"`. 즉 `Y`가 아닌 값(`""`, 소문자 `y` 포함)은 모두 `N`으로 바뀝니다.

**`Cdn`** (처방 가능 여부·문구)
1. 이력 또는 선택코드 없음 → `undefined`
2. `R0e` 참 → `{ 처방불가: true, 오류메시지: "환자가 이미 다른 2개 질환으로 처방받았습니다." }`
3. `N0e` 결과 없음 → `undefined`
4. `Y`이고 누적 ≥ 20 → `{ 처방불가: false, 오류메시지: "환자가 {질환명}으로 {누적}일 처방받았습니다." }`
5. `N`이고 누적 > 0 → `{ 처방불가: true, 오류메시지: "환자가 타원에서 {질환명}으로 처방받았습니다." }`
6. 그 밖 → `{ 오류메시지: "" }`

**`$dn`** (의사 한도 이내일 때, [pilot-herbal-doctor-limit.md](pilot-herbal-doctor-limit.md) 참조)
1. `N0e` 결과 없음 + `R0e` 참 → `{ 코드: "", 전액부담선택가능: false }`
2. `N0e` 결과 없음 → `{ 코드: "G", 전액부담선택가능: true }`
3. `Y`, 누적 < 20 → `G`, true
4. `Y`, 누적 ≥ 20 → `U`, false
5. `N`, 누적 = 0 → `G`, true
6. `N`, 누적 > 0 → `{ 첩건본인부담률구분코드: "" }` (선택가능 키 없음, 호출부는 `?? false`)

`본인일부부담이지만전액부담선택가능함`이 참이면 화면에서 일부부담(`G`) 대신 전액부담을 고를 수 있는 선택지를 보여 줍니다.

## 서버 이전 시 주의

- **두 함수의 불일치(버그로 보임):** `$dn`은 선택 질환 이력이 **없을 때만** 다른 2개 질환 규칙을 적용합니다. 선택 질환 이력이 있으면(예: 01 Y 5 + 다른 질환 2개) 코드가 `G`가 되어 추가 버튼이 활성인데, `Cdn`은 "처방 불가"를 표시합니다. 고치지 않고 그대로 기록합니다.
- **20일 기준:** `>= 20`이 두 함수에 하드코딩돼 있습니다. 질환별 급여 투약일 상한인지 고시 대조 후 `regulatory-limits`로 옮길지 결정해야 합니다. 요청에 언급된 별도 "누적 투약일수 한도"는 이 20일 외에는 찾지 못했습니다.
- **`Y`/`N` 병합:** 같은 질환 행에 `Y`와 `N`이 섞이면 `Y`가 이기고 일수는 최대값입니다. 타원 이력이 이 기관 이력 하나로 가려집니다.
- **알 수 없는 등록 여부:** `Y`가 아닌 값(`""` 포함)은 `N`으로 바뀝니다. 웹 경로에서 API가 필드를 빼면 `""`가 되고, 누적 일수가 있으면 "타원" 처방 불가가 됩니다. 의도인지 확인이 필요합니다.
- **웹과 앱 데이터 차이:** 웹은 선택 질환 한 건만 받으므로 다른 2개 질환 규칙이 웹에서는 절대 발동하지 않습니다. 앱만 전체 질환 목록을 받습니다. 서버는 심평원 데이터를 어떻게 받을지(데스크톱 에이전트 경유) 정해야 합니다.
- **타이밍:** `$dn`은 질환 코드 `watch`에서 그 순간 캐시된 이력으로 돕니다. 웹에서는 이력 조회가 `$dn` 뒤에 일어나므로 첫 선택은 이전/빈 이력으로 판정됩니다.
- **조회 연도:** 이력은 `new Date().getFullYear()` 기준(올해)입니다. 진료 기준일과 다를 수 있습니다(연초에 작년 날짜 차트 수정 등).
- **문구 조사:** `으로`를 받침과 무관하게 붙입니다("안면신경마비으로"). 서버 문구를 바꾸면 현행과 문자열이 달라집니다.
- `M0e`에 없는 질환 코드(00-06 외)로 이력이 있으면 `Cdn`이 `TypeError`를 던집니다.
