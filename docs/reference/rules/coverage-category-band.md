# 보험구분과 처방 카테고리 대역 일치

## 요약

- 보험구분(`건보`·`급여`·`자보`·`산재`·`일반`)을 정하거나 바꿀 때, 새 보험구분에서 쓸 수 없는 처방 라인을 골라냅니다.
- 판단 기준은 `카테고리숫자코드` 묶음(자보 71·72·73·74, 산재 92·93·94, 첩약 시범사업 35)과 몇 가지 특정 수가코드(`40721` 복잡추나 80%, 비대면 `91001`~`91004`, `91000…`)입니다.
- 건보 대역(29·31·33·34)과 비급여 대역(45·51~56)은 어느 보험구분에서도 골라내지 않습니다. 설계 문서의 "건보 31·33·34·35, 비급여 51·53·54" 대역 일치와는 **다릅니다**.
- 골라낸 라인은 확인 대화상자를 거쳐 처방에서 지운 뒤 저장합니다. 진료 저장·완료 시점에는 클라이언트 검사가 없습니다.

## 서버 이전 시 주의

- **설계 문서와 실제 동작이 다릅니다.** `clinical.md`의 `COVERAGE_CATEGORY_MISMATCH` 대역(건보 31·33·34·35 / 비급여 51·53·54 / 자보 73·74 / 산재 93·94)은 현행 클라이언트가 강제하지 않습니다. 현행은 "다른 보험 전용 카테고리 차단" 방식입니다. 자보·산재 진료에 건보 침술(`33001001`)이나 진찰료(`31001001`)가 있어도 막지 않습니다. 비급여 라인은 모든 보험구분에서 허용됩니다. 어느 쪽을 서버 규칙으로 삼을지 결정이 필요합니다.
- **대역에 없는 자보·산재 카테고리.** 자보 71(입원)·72(검사)와 산재 92(검사)도 차단 대상입니다. 설계 문서 대역에는 빠져 있습니다.
- **첩약 시범사업은 건보 + 시범사업 선택일 때만** 허용됩니다. 의료급여(`급여`)에서는 객체가 있어도 차단됩니다.
- **비대면 코드 비대칭.** `91001`~`91004`는 비대면 시범사업이 켜진 건보·급여에서만 허용됩니다. 실제 호출부는 4번째 인자를 건보일 때만 참으로 넘기므로 급여에서는 늘 차단됩니다. 반면 `91000…` 접두 코드는 비대면 여부와 무관하게 건보·급여에서 허용됩니다.
- **검사 시점.** 보험구분을 바꿀 때만 돌고, 진료 저장·완료 때는 클라이언트가 다시 검사하지 않습니다. 완료 시 `COVERAGE_CATEGORY_MISMATCH`는 새 동작입니다.
- **처리 방식.** 현행은 사용자 확인 뒤 라인을 **삭제**합니다. 서버 설계(`front-desk.md` 보험구분 변경)는 삭제 대신 `invalid` 표시로 바꿉니다. 진료 화면에서는 승인된 처방(`승인여부`)이 있거나 내원 상태가 `수납완료`이면 보험 변경 모달을 열지 않고 안내만 합니다(`TreatmentViewBoardChangeInsuranceTypeButton.vue.js:110-135`). 이 부분은 이 규칙 밖입니다.
