# 첩약 시범사업 청구 검사 (C0001–C0012)

## 요약

- 건보 첩약 시범사업 진료의 청구 오류를 C0001–C0012 열두 가지로 검사합니다(`tBt`).
- `tBt`는 열두 함수를 모두 호출하지만 결과 목록에는 **C0001, C0003, C0005만** 넣습니다. 나머지 아홉 개는 계산 후 버립니다.
- 진료 화면 실시간 경고(`HFt`)는 허용 코드 집합으로 다시 거르므로 화면에 나오는 것은 **C0001, C0003뿐**입니다.
- 버려지는 검사 중 C0004·C0010은 날짜 인자 순서가 뒤집혀 있고, C0007은 존재하지 않는 상수를 참조해 절대 발동하지 않으며, C0012는 호출부가 입력을 주지 않아 발동하지 않습니다.

## 서버 이전 시 주의

- **버려지는 검사:** C0002, C0004, C0006–C0012는 계산만 하고 결과에 넣지 않습니다. 의도적으로 끈 것인지, 서버 청구함에서만 쓰려는 것인지 확인이 필요합니다. 서버가 그대로 켜면 현행보다 훨씬 많은 경고가 나옵니다.
- **C0004·C0010 날짜 버그로 보임:** `Df(이전, 현재)`라 이전 기록이면 음수가 되어 `<= 10`/`<= 1`이 항상 참입니다. 의도는 `Df(현재, 이전)`으로 보입니다. 또한 비교 대상이 "가장 최근 1건"이라 현재보다 뒤 날짜 기록이 있으면 앞 날짜 기록은 무시됩니다.
- **C0007 사문(死文):** `Kp.조제탕전료`가 없어 `startsWith(undefined)`(문자열 `"undefined"` 비교)가 되므로 절대 발동하지 않습니다. 의도한 접두어는 `904`(90411·90412·90421·90422)로 보입니다. "길이 > 5 = 가산"이라는 판정도 가산 코드 체계 확인이 필요합니다.
- **C0012 사문:** 유일한 호출부 `HFt`가 `진료의목록`을 넘기지 않아 발동하지 않습니다. 서버는 진료의 주민번호를 직접 갖고 판정할 수 있습니다.
- **예외로 전체 실패:** 첩약 라인에 `기타정보`가 없으면 C0002가, 질환코드 `00`이면 C0008이 `TypeError`를 던집니다. `tBt`가 모든 검사를 순서대로 부르므로 이 경우 C0001·C0003 경고까지 함께 사라집니다.
- **C0009 문구와 동작 차이:** 문구는 "제 1부상병"이지만 코드는 아무 부상병 위치나 허용합니다.
- **C0003 자동 수정 범위:** 검사는 `34001001`만 보는데 자동 수정은 `34002001` 한방조제료까지 지웁니다.
- **C0005:** 첫 첩약 라인만 봅니다 ([pilot-herbal-approval-required.md](pilot-herbal-approval-required.md)).
- **실행 조건:** `tBt`는 `보험구분`이 `건보`/`급여`이고 `한방첩약시범사업` 값이 있을 때만 돕니다.
- **시간대:** 날짜 비교는 브라우저 로컬 시간 기준입니다. 서버는 Asia/Seoul로 고정해야 합니다.
- **최근진료기록 범위:** `최근진료데이터`가 얼마나 과거까지 포함하는지는 서버 응답에 달려 있습니다. 10일 규칙을 서버로 옮길 때는 서버가 직접 기간 조회를 해야 합니다.
